## Backend capability

`GET /api/routes` remains compatible with existing callers. Optional filters:

- `q`: literal case-insensitive text across route names, description, origin and destination.
- `origin`, `destination`: literal case-insensitive text filters.
- `routeType`: `DAILY_COMMUTE` or `INTERCITY`.
- `period`: `morning` or `evening`, requiring a nonempty configured departure.
- `sort`: `name` (default), `fare`, or `distance`, with stable tie ordering.

Example: `/api/routes?origin=addis&destination=hawassa&routeType=INTERCITY&sort=fare`.

Invalid values, oversized text and repeated/structured parameters return HTTP 400. User input stays in bound SQL parameters; wildcard characters are treated literally. The Android screen still filters its existing local route stream; it does not call these server filters. This search does not reserve seats or confirm availability for a travel date.
