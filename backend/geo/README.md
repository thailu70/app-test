# Free location search and road distance

Application endpoints use private `http://photon:2322` and `http://osrm:5000` by default; override with `PHOTON_URL` / `OSRM_URL` only for your own services. There are no public demonstration server fallbacks and no paid API calls. Search falls back to named route stops when Photon is unavailable. Routing returns an explicit unavailable response; it never charges from an invented straight-line distance.

From this directory on the VPS, run `bash prepare-osrm.sh` to download the Ethiopia OpenStreetMap extract and prepare an OSRM graph. The script refuses to replace a running graph. Preparation needs spare memory and time; perform it separately from app builds. Validate disk/RAM first. The Compose services do not expose any host ports and join the existing `routepass_internal_net`.

For an existing live graph, use `bash update-osrm.sh prepare` instead. It freezes the official latest download to its dated Ethiopia extract, verifies Geofabrik's published MD5 for download integrity, records SHA-256, and builds a separate staging directory with the **exact running OSRM image ID**, 3 GB RAM and 1 CPU limits. It checks five private full-geometry routes in Addis Ababa and across Ethiopia, without exposing another port. Preparation needs 4 GB available RAM and 5 GB free disk; the live graph, API and Photon stay untouched. Metadata, source headers, graph checksums and private route results are retained under `updates/ID/manifest.json` and adjacent files. Preparation failure retains staging files for diagnosis; nothing is recursively deleted.

After reviewing the manifest, run `bash update-osrm.sh activate ID`. It rechecks the pinned engine, safe absolute paths and every graph checksum, stops only OSRM, renames the old graph to `data/osrm-backup-ID`, and recreates only OSRM with its existing Compose configuration and pinned image (no pulls or upgrades). Route checks run again after the brief routing interruption; failure restores the old graph automatically. `bash update-osrm.sh rollback ID` explicitly restores a retained backup. Do not edit or reuse the active/backup directories manually. Keep the update script in the same real directory as the live `compose.yml`; never bypass `prepare-osrm.sh`'s running-graph safeguard. The source date describes the OSM extract, not real-time traffic or guaranteed agreement with independently updated map tiles. Photon search data is updated separately.

The app requests the full road polyline; exceptionally large responses are bounded to at most 20,000 points using a small geometry tolerance. Route access points must snap within 500 metres of the car road network, so an inaccessible pin returns a clear routing error instead of a long invented connector. Road geometry is for navigation display; the taxi meter continues to use validated recorded GPS movement and the agreed waiting rules.

For Photon, run `bash prepare-photon.sh`. It downloads official release 1.3.0, verifies the GitHub asset SHA-256 digest, downloads the matching regional Horn of Africa JSON data and its upstream checksum, then imports Ethiopia only with local, English, Amharic and Oromo names when available. It uses a fresh staging directory and refuses to replace existing/running data. Data import replaces its target, so updates must always use a separate staging directory. The import container is capped at 2 GB RAM and 1.5 CPU. Validate a real landmark search before declaring the service ready. A failed import retains its staging data for diagnosis.

An Ethiopia-only search database avoids the planet database’s substantial resource requirements. Actual capacity and search coverage must be tested; do not advertise full search readiness until a real landmark query succeeds. Suggested pickup results still require user confirmation on a map. OSRM uses the car profile and does not certify heavy-vehicle clearance or legal cargo routes.
